# mdnote — agent guide

What the tool is and how to use it: README.md. This file is what must stay true when you change the code.

## Map (runtime order)

- `src/cli.ts` — entry (`mdnote <file.md>` / `wait` / `comments` / `clear` / `stop` / `list`; any non-subcommand argv is a review invocation), find-or-attach: it POSTs `/api/open` to the server named by the global lock, or spawns itself detached with the internal `--serve` flag, stdout/stderr pointed at the state-dir log (the serve process is the only one that runs `startServer`, writes the lock, and cleans it up). Review dynamic-imports `server.ts` so `comments`/`clear` keep working even when the server is broken.
- `src/lock.ts` — the state dir (`~/.local/state/mdnote`, `$XDG_STATE_HOME` honored) and what lives in it: the global lock `server.json` (`{host, port, pid}` read/write plus pid-liveness), `logPath()` for `server.log`, and `registryPath()` for `registry.json`.
- `src/registry.ts` — the persisted working set (`registry.json`: absolute path → last-touched ISO stamp), loaded on cold start and rewritten on every touch.
- `src/config.ts` — reads `~/.config/mdnote/settings.json` (`$XDG_CONFIG_HOME` honored), validates warn-and-drop per key, merges over defaults into a `ResolvedConfig`; `updateSettings()` is the one writer, behind `PATCH /api/settings`.
- `src/themes.ts` — the theme roster (`THEME_MODES` + `THEME_NAMES` = `THEMES`), shared by config validation, the picker, and the theme tests; each named palette has a token block in `web/themes.css`.
- `src/actions.ts` — pure action catalog (`ActionId`s, labels, default keybindings) and keybinding spec parsing; shared by `config.ts` and the frontend.
- `src/render.ts` — markdown-it with a rule stamping `data-source-line="start-end"` (plus `data-line-start`) on block elements, and code-block content wrapped into per-line `.code-line` spans carrying absolute source lines; `stampedBlocks()` lists the line ranges of the stamps that reach the DOM.
- `src/anchor.ts` — `locate()` matches rendered-text selections against Markdown source, down to the column; `reanchor()` re-resolves annotations after edits; `occurrenceOf()` turns a stored column back into the match index the client paints. The load-bearing module: staleness is `locate()` returning null.
- `src/server.ts` — Bun.serve API + SSE + file watchers over a registry of open files (path → SSE clients, restored from `registry.json` at startup); bundles the frontend at startup, runs the idle clock.
- `src/store.ts` — sidecar JSON read/write (`<file>.mdnote.json`), atomic via temp-file + rename.
- `src/types.ts` — shared types. Import from here; never redeclare.
- `web/anchor-dom.ts` — framework-free DOM math (selection → `data-source-line` → line ranges, text-node search for highlight ranges). No Preact imports, by design.
- `web/hover.ts` — the hover-preview timing state machine (rest to open, grace to close), DOM-free so it tests without a browser.
- `web/general-note-size.ts` — the general note composer's resize math (symmetric growth, min/viewport clamp), DOM-free for the same reason.
- `web/help.tsx` — the `?` cheatsheet dialog and `helpGroups()`, which resolves it against the action catalog and the injected config.
- `web/main.tsx` — Preact chrome (sidebar, popover, SSE state) around the doc island.

## Invariants

- **The server owns source-position truth.** The browser sends rendered text and approximate lines; `locate()` normalizes them to source (stripping `**`/`_`/etc., treating whitespace runs as equal so selections cross soft-wrapped lines). Don't move anchoring into the client — rendered text and source text differ, and only the server has both.
- **Which match is a server decision; the client only counts.** When a block holds the anchor text more than once, a selection inside one stamped block sends `occurrence` (`{index, total}` among the overlapping-counted matches in that block's whitespace-collapsed text), and `locate()` takes match `index` among the candidates starting in the block's lines only when its own count equals `total`. Candidates are one list in source order: the exact matches plus the normalized matches no exact one contains (the same text crossing markup or a soft wrap), so an exact match elsewhere never hides a markup-crossing one; an anchor holding markdown punctuation normalizes lossily (`(x)` would match every bare `x`), so its normalized matches count only when it has no exact one. The resolved position persists on text annotations as `columnRange` + `textBefore`/`textAfter` (all three or none; never on block or doc-wide notes); `reanchor()` takes them as hints (nearest line, then agreeing context, then nearest start column), rewrites them on every successful re-anchor and removes them when the new result has none, while a stale annotation keeps its old ones like its `lineRange`. No position is better than a wrong one: a tie the hints can't break yields lines without columns. `occurrence` is wire-only in both directions, never in the sidecar, `comments --json`, or the envelope: the annotations GET derives `occurrences` (a sibling of `reviewPending`, keyed by id) from each `columnRange` through `occurrenceOf()` over `stampedBlocks()` and the same candidate list, so a position created from an occurrence converts back to that occurrence, which `tests/render.test.ts` pins to the stamps that reach the DOM. The client takes match `index` in the innermost block holding `lineRange[0]` only when that block's own count equals `total`; otherwise it paints the first match, as it does for an annotation without columns.
- **The doc island's DOM stays byte-identical to the server's HTML.** Preact renders nothing inside `#doc` (filled via `dangerouslySetInnerHTML`, touched only through refs). Highlights use the CSS Custom Highlight API exclusively — no `<mark>` wrapping — so selection offsets and re-anchoring math never see a mutated DOM.
- **Set highlights by name, never `CSS.highlights.clear()`.** The registered names (`mdnote-open-d0`..`d8`, `mdnote-stale`, `mdnote-pending`, `mdnote-draft`, `mdnote-focus`) are owned by four different effects; `clear()` wipes the whole registry and reintroduces a fixed bug (pending highlight vanishing on annotation repaint).
- **Nesting depth drives annotation color; status outranks depth.** Every saved annotation's depth is derived at paint time (`computeDepths`: how many other saved annotations properly contain its resolved range — blocks and text unified, partial overlaps are siblings, never persisted) and picks a hue from the 3-cycle `--hl-open`/`--hl-open-1`/`--hl-open-2` (gold/sky/plum — red-green-CVD-checked, see the token comment; any new hue must pass the same simulation). Text paints one highlight name per depth with priority = depth so inner shows over outer (same-name ranges flat-fill their union, which is why one name can't do it); open block boxes wear translucent wash + solid border in the depth hue and deeper boxes render later; a containing box inflates its halo per level of boxes inside it (`computeHeights` → `NEST_PAD`), so containment reads as geometry, never as coinciding edges. Stale stays gray at any depth (line-through text, dash-bordered box) so staleness is never missed — the accepted cost is that stale-in-stale and open-under-stale overlaps don't visually separate. Click and hover resolve the innermost hit (deepest text range, then smallest box).
- **Line-number conventions differ by one.** `data-source-line` and `Annotation.lineRange` are 1-based inclusive; markdown-it's `token.map` is 0-based exclusive-end (`[s, e)` → `s+1`-`e`). This conversion is the repo's off-by-one hotspot; `tests/render.test.ts` pins it per block type.
- **Fences stamp `<pre>`, not `<code>`.** markdown-it's default fence renderer puts token attrs on `<code>`; `render.ts` overrides it so the innermost stamped ancestor is always the block element.
- **No localhost anywhere in the frontend.** Remote serving is first-class: all fetches are root-relative, SSE derives from `window.location`.
- **Every color literal lives in a token block: `:root` in `style.css`, or a `:root[data-theme="<name>"]` block in `themes.css`.** The root tokens carry light and dark via `light-dark()`; a named palette block (DaisyUI's values, oklch verbatim) sets `color-scheme`, the surfaces, the accent pair, three depth-hue carriers with a wash strength, and the syntax colors, and the shared `:root[data-theme]:not(...)` rule derives every other token from those with `color-mix()`. Theme is `data-theme` on `<html>` (from settings.json, applied pre-paint by the inline script in `index.html`; absent for `system`). `tests/style.test.ts` pins the no-literals rule for both stylesheets and the frontend TS; `tests/themes.test.ts` resolves every theme's tokens (via `tests/color-math.ts`) and pins red-green-CVD separation of the three depth hues plus text contrast, so a new palette or a retune must pass it — anything new that colors pixels goes through tokens.
- **The server owns settings truth.** `loadConfig()` merges settings.json over defaults and the server injects the resolved result into `index.html` as `window.__MDNOTE_CONFIG__` per request (page reload applies edits). The frontend never merges or persists settings itself: the theme picker, the reading-line toggle, and a resize of the general note composer apply locally and send `PATCH /api/settings`, which `updateSettings()` validates (only `theme`, `readingLine`, and `generalNoteSize`; a hand-broken file is refused with 409, never replaced) and writes back preserving every other key, after which a `settings` SSE event tells every open tab to refetch `GET /api/settings`. A failed write leaves the change session-only and says so in a toast.
- **What may be served is one predicate.** `isMarkdownPath()` plus an existence check gates both `POST /api/open` and document-GET auto-registration; both 404 identically. `/api/*?file=` serves only registered files — auto-registration happens on document GETs alone. The one carve-out: image files (`IMAGE_TYPES`) are served raw, and only from under a registered doc's directory, so relative image references in a doc render without opening the rest of the disk.
- **Button labels: contextual names the verb, global names the object.** A button inside a context that already names its object (the annotation popover, a sidebar entry) shows one short verb (Edit, Delete, Save); a button with no surrounding context names its object (Copy markdown). `src/actions.ts` keeps the descriptive catalog label for tooltips and the help dialog regardless of what a button displays (`ActionButton`'s `label` prop overrides the visible text only).
- **The registry persists paths, not watchers.** Restored entries only populate the file map; a watcher still appears when that file's first SSE client connects. `loadRegistry()` drops entries whose file no longer exists or that went untouched past the 14-day age-out; the touch points are `register()` (`/api/open`, auto-register) and a document GET of an already-registered path.
- **Blockness is persisted, never inferred.** `Annotation.block` is set at creation from a whole-block gesture (one block, or a selection exactly covering a consecutive sibling run of blocks — anything partial stays a text highlight) and carried through `reanchor()`; presentation never guesses it from text coverage. A block annotation paints only the `.block-box` overlay (depth-hued wash + border when open, gray dashed when stale), never a text highlight — one visual, one meaning. Boxes are chrome outside `#doc`, measured as the union of the run's block elements (`blockRun()` re-derives the run from the anchored range) and re-measured on doc reload and window resize, and clicks hit-test the box rects (padding included, smallest hit wins) after the text-range test. Boxes on adjacent blocks whose halos collide are pulled apart to a visible gap (`separateBoxes()`, deep overlaps meaning nesting stay put); hit-testing sees the separated rects, so visuals and click targets never disagree.
- **Hover previews an annotation popover, click pins it.** One `openAnn` state carries `pinned`; only an unpinned popover closes on mouse-out, and clicking or entering edit mode sets `pinned`, so a draft never dies to a stray mouse move. Hover resolves its target exactly like the click path, in the same order — text ranges via `caretAt()` (innermost first), then block-box rects — because boxes are `pointer-events: none` chrome and the doc island has no per-annotation elements to take mouseenter; the sample is rAF-throttled and inert while a note form is open. The edit/delete actions (`e`/`shift+d` by default) resolve their target in pointer-first order: hovered sidebar entry, then the open doc popover, then the last-clicked entry — an open popover outranks the focus it never set.
- **The help dialog is a keybinding cheatsheet, updated in the same round.** It lists only keybound actions (resolved through `ACTIONS` plus the user's bindings, so a remap shows their keys), each with a description only where the behavior is non-obvious; a new keybound action is incomplete until `ROWS` in `web/help.tsx` carries it. Everything else is taught in place: the dialog's intro line names the core gesture (click a block / highlight text), buttons carry tooltips, and intuitive gestures (hover to preview, click to pin) get no row at all.
- **Line numbers are CSS pseudo-element content, never DOM text.** The gutter (settings.json `lineNumbers`, class set pre-paint on `<html>`) paints `attr(data-line-start)` / `attr(data-line)` via `::before`, so numbers can't enter selections, clipboard, or the anchoring math. `wrapCodeLines()` keeps a code block's `textContent` byte-identical (newlines stay as text between `.code-line` spans, hljs spans re-balanced per line); prose gets block-start numbers only, since soft-wrapped visual lines have no source mapping.
- **The reading line is chrome, like the block boxes, but painted over the text.** `ReadingLine` (settings.json `readingLine`) resolves the caret under the pointer with `caretAt()` and paints one `.reading-line` div outside `#doc`, in page coordinates, as a translucent wash above the content (under the text, a code fence's or table head's own background would hide it), one computed line-height tall — taken from the enclosing `pre code` when there is one, else the stamped block, so code and prose get their own pitch — centered on the caret's glyph box. It updates only on pointer moves (rAF-sampled) and on the arrow actions, so scrolling leaves it on the line it marked and a pointer over the sidebar or a gap keeps the last line; a doc reload or resize drops it until the next move rather than trusting stale geometry. `reading-line-down`/`-up` (↓/↑) step it through `textLines()` — the doc's visual text lines from every text node's client rects, fragments on one line collapsed — and scroll so the band sits at the viewport's center (clamped at the page's ends); after a step the keyboard owns the band and pointer moves are ignored until the pointer travels `POINTER_RECLAIM_PX`, so a resting hand can't yank it away mid-read. The step actions register only while the band is mounted, and `useActionDispatcher` leaves an unregistered action's key to the browser, so bare arrows scroll normally while the line is off. No transition on the band: a recenter moves page and band together, and an eased `top` would visibly lag the jump. While the line is on, the band's block (reported through `onTarget`, null once the band drops) is the target of `annotate-block` and of the hover bar, so `c` notes the line being read; the pointer's block is the fallback until a band exists.
- **A submit resolves waiters; rounds are stamped once.** `mdnote wait` blocks on `GET /api/wait` (stdout is the `ReviewEnvelope` JSON alone — no prose; the URL goes to stderr) and a pending waiter counts as a client for the idle clock. `POST /api/submit` 409s with no waiter, excludes drafts, stamps `round` only on annotations that lack it (a re-delivered note keeps its original round), and clears the waiters before `persist` broadcasts, so one `annotations` event carries both the round stamps and `reviewPending: false`. The round counter lives in the sidecar's `lastRound`, not on the annotations, so clearing annotations never resets numbering; every sidecar write path (`persist`, reanchor) preserves fields beyond `annotations`. The frontend learns pending state solely from `reviewPending` on the annotations response; the Submit block lives in the sidebar footer (shown only while a wait is pending), and submitting with zero notes is the approve path, never an error. Submit is keybound (`submit-review`, default `mod+enter`) behind a confirmation dialog (Enter confirms; its "Don't ask again" checkbox is session-only, not a settings key); the note form's textarea stops propagation of its own mod+enter save so a form save never doubles as a review submit.
- **Stale annotations are never silently dropped.** `reanchor()` flips them to `status: "stale"` and keeps the old `lineRange`; only a human (or explicit `clear`) removes them. The one exception is drafts (below), which `reanchor()` deletes when their text can't be re-found.
- **A draft is a real annotation with `draft: true`, and it survives exactly one thing: interruption.** The pending form persists it on the gesture (`POST` with an empty note, debounced `PATCH` while typing; save promotes via `PATCH {draft: false}`); Escape, click-away, and a lost anchor all delete it, so a draft in the sidecar always means an interrupted session. Drafts are hidden from the sidebar, `mdnote comments`, and submit envelopes — their only handle is the doc visual (`mdnote-draft` highlight or `.block-box.draft`, dash-edged, distinct from saved and pending), and clicking it reopens the form with the text (no auto-opened forms on load; hover passes through). The active draft paints only the pending visuals; a reload keeps an open draft form alive, re-deriving its anchor when the doc island was rewritten. Doc-wide notes ("General note") don't draft — no anchor means no resume handle.

- **The general note composer is a centered dialog; only a finished drag writes its size.** `shift+c` and the sidebar button open one `GeneralNoteComposer` over the scrim, and it counts as an open note form, so hover preview is inert under it. Escape and a mousedown outside the panel cancel it — mousedown, not click, so a resize drag that ends outside never cancels. It stays centered, so it grows symmetrically: `resizeGeneralNote()` turns a pointer travel of dx into 2·dx of width, keeping the dragged edge under the pointer. `clampGeneralNoteSize()` bounds the size during the drag and again at render (a size saved on a big screen loads on a small one), and the render-time clamp is never written back: pointer moves set local state only, and pointer-up sends the one `PATCH` of `generalNoteSize` (whole pixels; absent means the default size).

## Hiccups

- **Frontend JS bundles once at server startup** (`Bun.build` on `web/main.tsx`). Restart the server (`mdnote <file.md>`) to see `web/` TS changes; `style.css` is read per request, so CSS changes only need a page reload.
- **The shebang on `src/cli.ts` is load-bearing.** `bun link` symlinks the bin straight to the file; without `#!/usr/bin/env bun` the shell executes it as a shell script.
- **Watchers are `fs.watch` on the parent directory, resolved by mtime sweep** (50ms debounce per file), not per-file watches — editors and agents replace files by rename, which per-file watches lose track of, and the rename event carries the source (temp-file) name, so events can't be matched by basename either: any event stats every watched basename in the dir and schedules the ones whose mtime moved. One watcher per directory serves every registered file in it, created lazily when that file's first SSE client connects. The watcher covers external writes only: sidecar mutations through the API broadcast directly from `persist` as a lighter `annotations` SSE event (clients refetch annotations only — no doc re-render; this is what keeps per-keystroke draft PATCHes cheap), file changes broadcast `update` (full reload), and the server marks its own sidecar writes seen (`markSeen`) so they don't echo back as a second broadcast.
- **The global lock can be stale.** A lock whose pid is dead counts as no server everywhere (cold start, `stop`, `comments`/`clear`). `comments`/`clear` give the API ~300ms and fall back to reading the sidecar directly on a dead lock, a timeout, or a non-2xx (the server 404s files it hasn't registered); treat the sidecar as the source of truth, the API as an optimization.
- **Only SSE clients hold the server open.** The idle clock (5 min, `MDNOTE_IDLE_TIMEOUT_MS` overrides it for tests) runs whenever the total client count across every registered file is zero, starting at boot, so a server nobody opens a tab on dies on its own; `onIdle` (the serve process passes `process.exit(0)`) is what makes the clock exist at all, so a `startServer` call without it never times out. A registration via `/api/open` isn't a client and doesn't stop the clock.
- **SSE streams must never sit idle.** `Bun.serve` closes a stream after 10s of silence, so the server pings every connected client with a `: ping` comment every 6s (`MDNOTE_PING_MS` overrides it for tests) rather than raising `idleTimeout`, which caps at 255s and only delays the close. The frontend refetches on the EventSource `open` event as well as `update` (skipping the first open), so a reconnect from any cause pulls current state instead of leaving the tab on stale content.
- **The detached server's stdout/stderr go to `server.log` in the state dir**, truncated per cold start by the spawning CLI (it opens the fd with `"w"`), so bundle and watcher warnings are diagnosable after the fact.
- **The lock appearing is the cold-start readiness signal.** The serve process writes it only after `Bun.serve` is listening, so the spawning CLI polls for the lock file rather than the port.
- **JSX is Preact** via root tsconfig (`jsxImportSource: preact`), which `Bun.build` picks up. Don't add a per-file pragma or React types.

## Verifying changes

`bun test` (263 tests: render stamps, code-line wrapping and stamped-block ranges, anchor matching, which-match columns and their re-anchoring, draft reanchor deletion, nesting depth/height containment and hue-cycle pinning, sidecar, draft flag round-trip and promotion, style tokens, theme palettes (token completeness, CVD separation, contrast), settings read/write and the settings route, general-note resize math, hover-preview timing, help-row resolution, server registry/SSE scoping, rename-write detection and mutation broadcast, keepalive, review wait/submit round-trip and round stamping, idle shutdown, lock liveness, registry persistence) and `bunx tsc --noEmit` — both must be clean. Browser drag-selection has no automated coverage: any change to selection, popover, or highlight code needs a browser poke — use the `browser-test` skill (drives the real UI headlessly with agent-browser: drag-select, annotate, edit the file, assert sidecar/highlights).
